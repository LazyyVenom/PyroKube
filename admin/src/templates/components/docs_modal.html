PyroKube Developer & Application Specification Guide

1. Application Image & Health Endpoint Specs

PyroKube runs native Kubernetes liveness and readiness health check probes on your application container port:

  • Declare target container port with EXPOSE <port> in Dockerfile.
  • Expose a GET /healthz or HTTP 200 endpoint for automated health checks.
  • Container health probes run every 10 seconds automatically.

2. Inter-Service Mesh Connection URIs

Once a managed catalog engine (Postgres, Redis, Mongo, RabbitMQ) is Active, its internal K8s cluster DNS endpoint is immediately discoverable from any custom app container:

PostgreSQL: postgres-main.pyro-postgres-main.svc:5432
Redis Cache: redis-cache.pyro-redis-cache.svc:6379
MongoDB Store: mongo-store.pyro-mongo-store.svc:27017
RabbitMQ Broker: rabbitmq-main.pyro-rabbitmq-main.svc:5672

3. Zero-Dockerfile Auto Stack Conversion

Deploying from GitHub does not require writing a custom Dockerfile! PyroKube automatically inspects root manifests and builds:

package.json → Multi-stage Node.js 20
requirements.txt → Python 3.11-slim
go.mod → 2-Stage Go Alpine Builder
index.html → High-speed Nginx Web
